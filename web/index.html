01 · Problem

Problem

Fulfillment corridors and backbone networks experience link outages at the same time that message-queue retry storms replay billing events against their settlement databases.

Congested Corridors and Replayed Invoices 300 Demands · 2,000 Billing Events

Consider a cross-country freight corridor (SEA1 → ORD5 → EWR7) or a 28-node, 120-link network carrying 300 active demands. Static shortest-path routing selects the shortest path on paper and keeps sending traffic into it even when Chicago (ORD5) closes in a blizzard or a wireless feeder link drops below 8.0 dB signal quality. Queues build up on the degraded hop, raising p99 path latency to 526.47 ms and missing SLAs on 35.67% (107/300) of demands.

Every rerouted shipment or metered bandwidth batch also emits billing events over at-least-once queues such as Amazon SQS. During network timeouts, SQS redelivers the same message up to 5x. A naive floating-point billing processor charges customers multiple times (245 duplicate charges totaling $17,792.88 overbilled in our 2,000-event benchmark) and accumulates 60¢ of IEEE-754 rounding drift. RouteLedger combines a capacity-aware Python graph solver (0.121 ms p50 / 0.465 ms p99), a 3-check decision tree (100.0% accuracy on 150 incidents), and an idempotent SQLite double-entry ledger with 0 duplicate charges and $0.00 balance drift.

Scope & Benchmark Setup: All benchmarks run our pure-Python directed graph solver (route_ledger/network_router.py: M/M/1 queuing delay, snr_db ≥ 8.0 edge pruning, and 2-way residual flow splitting across 28 nodes, 120 links, and 300 demands) and SQLite BEGIN IMMEDIATE / WAL 60-thread concurrency (route_ledger/double_entry_ledger.py).

EXAMPLE · REROUTING AN ORD5 HUB CLOSURE & 60-MESSAGE RETRY STORM

Tracing SEA1 → EWR7 (3,200 units/hr) During an ORD5 Blizzard Closure

When SEA1 inducts 3,200 units/hr bound for EWR7 (≤ 24.0h CPT target) while ORD5 closes in a snowstorm and SQS replays settlement messages 5x, the request moves through four steps in route_ledger/:

Step 1 · Edge Pruning & Split (0.12 ms) Static routing through ORD5 stalls all 3,200 units. RouteLedger prunes zero-capacity ORD5 edges and routes 3,200 u/hr via SEA1 → SLC2 → CVG3 → EWR7 at 12.6h transit and $1.24/unit (100.0% CPT met).
Step 2 · 3-Check Fault Tree (0.014 ms) OperationalWorkflowEngine checks vfd_motor_temp_c > 85.0 (62.0°C) and downstream_chute_fill_pct > 92.0 && secondary_lane_available (98.4%), isolating DOWNSTREAM_CHUTE_GRIDLOCK_DIVERT in 2 checks.
Step 3 · Grounded Bedrock Memo Verified solver and fault-tree JSON is sent to Amazon Bedrock (us.amazon.nova-lite-v1:0), which formats an operator dispatch note directly from measured corridor state rather than raw log text.
Step 4 · SQLite ACID Settlement IdempotentSettlementLedger computes US-WA (10.25%) tax via Decimal(ROUND_HALF_UP) and posts balanced debit and credit entries inside BEGIN IMMEDIATE. Across 60 concurrent SQS deliveries (12 × 5x), 48 duplicates are rejected with 0 double charges.

03 · Implementation

Implementation

The constrained shortest-path solver, 2-way residual flow splitter, 3-check operational decision tree, and SQLite BEGIN IMMEDIATE double-entry ledger in route_ledger/ are built with the Python standard library.

FLOW SPLITTING & INTEGER-CENT ACCOUNTING

Residual Multi-Path Routing and Atomic Double-Entry Settlement

When a single corridor cannot carry a large shipment alone, sending 100% of the load down one alternate route creates a second bottleneck. RouteLedger fills the lowest-cost healthy path up to its safe headroom and splits the remainder onto a second independent bypass. On the settlement side, every invoice is stored in integer cents (19,376,379¢) rather than binary floats, with every debit matched by equal revenue and tax credits inside a single SQLite write transaction.

CORE EQUATIONS & LOCKING SEMANTICS

M/M/1 Convex Edge Costs, Canonical SHA-256 Seals & BEGIN IMMEDIATE

In route_ledger/network_router.py, edge latency is modeled as d(e, Δf) = d_base + d_noise + d_queue((f + Δf)/C_eff) with hard pruning when outage == True or snr_db < 8.0, solved via heapq Dijkstra + 2-way residual augmentation (0.1211 ms p50 / 0.4648 ms p99). In double_entry_ledger.py, BEGIN IMMEDIATE acquires SQLite's reserved write lock up front, checks SHA256(canonical_json) against settlement_events(idempotency_key), and quantizes basis-point taxes (US-WA 1025, DE 1900, JP 1000, BR 2650) via Decimal.quantize(ROUND_HALF_UP).

MODULE 01 · MULTI-PATH GRAPH SOLVER route_ledger/network_router.py

28-Node / 120-Link Constrained Dijkstra & 2-Way Flow Splitter

  • Capacity & SNR Pruning: Checks real-time effective_capacity_mbps, residual_mbps, and snr_db ≥ 8.0 across 28 nodes and 120 directed links before admitting any edge into candidate paths.
  • Congestion-Aware Splitting: Models non-linear M/M/1 queuing delay and splits large demands across 2 residual subflows (6 split flows in the 300-demand suite) while reclaiming bandwidth as flows expire.
  • Measured Latency & SLA Gains: Cuts p99 path latency by 74.78% (526.47 ms → 132.80 ms) and SLA violations by 95.33% (107/300 → 5/300) in 0.1211 ms p50 / 0.4648 ms p99.

MODULE 02 · ACID DOUBLE-ENTRY LEDGER route_ledger/double_entry_ledger.py

SQLite BEGIN IMMEDIATE / WAL Idempotency & Multi-Region Tax Engine

  • Payload-Hashed Idempotency: Seals each UsageOrderEvent with canonical sorted-key SHA-256. Exact SQS replays return cached receipts (0 double charges), while mutated replays raise IdempotencyConflictError and roll back.
  • 60-Thread Concurrency Verification: Tested on both the 2,000-event benchmark (32,704.9 ev/s, 72 out-of-order watermarks) and a 60-worker ThreadPoolExecutor SQLite WAL retry storm (60 → 12 settled, 48 blocked).
  • Exact Cent Conservation: Enforces credit limits, inventory reservations, and Decimal(ROUND_HALF_UP) taxes across US-WA, DE, JP, and BR with 19,376,379¢ SUM(Debits) == SUM(Credits) (0¢ drift).

04 · Trade-Offs

Trade-Offs

Constrained polynomial graph search vs. global MILP solvers, immediate SQLite write locks vs. read-committed deduplication, and deterministic fault trees vs. raw-log LLM prompts.

SOLVER LATENCY & WRITE SERIALIZATION

Sub-Millisecond Graph Search and Upfront SQLite Write Locks

A global Mixed-Integer Linear Program (MILP) can optimize multi-commodity cost by another ~1%, but 50–200 ms solve times stall real-time routing. Constrained Dijkstra with 2-way residual splitting delivers 99.0% (297/300) of demands in 0.465 ms p99. On the ledger side, checking an invoice ID with a plain SELECT before INSERT lets two concurrent SQS workers pass the check simultaneously; BEGIN IMMEDIATE serializes writers up front with zero race windows.

REORDERING BOUNDS & PAYLOAD SEALS

Two-Subflow Split Cap and (idempotency_key, payload_sha256) Verification

Splitting a demand across k > 2 paths increases packet and freight arrival skew. Capping max_splits = 2 clears single-link bottlenecks while bounding arrival jitter. In double_entry_ledger.py, keying idempotency on (idempotency_key, payload_sha256) separates normal queue retries (is_duplicate=True) from payload mutations (IdempotencyConflictError + ROLLBACK).

PRINCIPLE 01 · HARD EDGE PRUNING

Filter Degraded Links Before Shortest-Path Search

Removing links with snr_db < 8.0 or zero residual capacity before heap expansion keeps shortest-path search off brownout corridors and reduces SLA breaches by 95.33%.

PRINCIPLE 02 · HASHED IDEMPOTENCY

Pair Idempotency Keys With Payload Digests

Storing payload_sha256 alongside idempotency_key turns accidental key reuse with a modified quantity into an immediate, auditable transaction rollback.

PRINCIPLE 03 · CHECK TELEMETRY FIRST

Run Structured Fault Checks Before Calling the LLM

Evaluating at most 3 telemetry predicates in 0.0029 ms locks in the root cause (150/150), so Amazon Bedrock writes clear operator instructions from verified facts.
