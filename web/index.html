01 · Problem

Problem

Fulfillment corridors and backbone networks experience link outages at the same time that message-queue retry storms replay billing events against their settlement databases.

Congested Corridors and Replayed Invoices 300 Demands · 2,000 Billing Events

Consider a cross-country freight corridor (SEA1 → ORD5 → EWR7) or a 28-node, 120-link network carrying 300 active demands. Static shortest-path routing selects the shortest path on paper and keeps sending traffic into it even when Chicago (ORD5) closes in a blizzard or a wireless feeder link drops below 8.0 dB signal quality. Queues build up on the degraded hop, raising p99 path latency to 526.47 ms and missing SLAs on 35.67% (107/300) of demands.

Every rerouted shipment or metered bandwidth batch also emits billing events over at-least-once queues such as Amazon SQS. During network timeouts, SQS redelivers the same message up to 5x. A naive floating-point billing processor charges customers multiple times (245 duplicate charges totaling $17,792.88 overbilled in our 2,000-event benchmark) and accumulates 60¢ of IEEE-754 rounding drift. RouteLedger v2 combines a time-expanded ATROPS multi-modal Pareto solver (0.094 ms p50 / 0.217 ms p99, -59.05% CO2e), a capacity-aware mesh graph solver (0.061 ms p50 / 0.268 ms p99), a 5-tool LEO MCP diagnostic registry with a JPL Power-of-10 C++ static gate (100.0% accuracy), and an idempotent SQLite double-entry ledger with 0 duplicate charges and $0.00 balance drift.

04 · Trade-Offs

Trade-Offs

Constrained polynomial graph search vs. global MILP solvers, immediate SQLite write locks vs. read-committed deduplication, and deterministic fault trees vs. raw-log LLM prompts.

SOLVER LATENCY & WRITE SERIALIZATION

Sub-Millisecond Graph Search and Upfront SQLite Write Locks

A global Mixed-Integer Linear Program (MILP) can optimize multi-commodity cost by another ~1%, but 50–200 ms solve times stall real-time routing. Constrained Dijkstra with 2-way residual splitting delivers 99.0% (297/300) of demands in 0.465 ms p99. On the ledger side, checking an invoice ID with a plain SELECT before INSERT lets two concurrent SQS workers pass the check simultaneously; BEGIN IMMEDIATE serializes writers up front with zero race windows.

REORDERING BOUNDS & PAYLOAD SEALS

Two-Subflow Split Cap and (idempotency_key, payload_sha256) Verification

Splitting a demand across k > 2 paths increases packet and freight arrival skew. Capping max_splits = 2 clears single-link bottlenecks while bounding arrival jitter. In double_entry_ledger.py, keying idempotency on (idempotency_key, payload_sha256) separates normal queue retries (is_duplicate=True) from payload mutations (IdempotencyConflictError + ROLLBACK).

Filter Degraded Links Before Shortest-Path Search

Pair Idempotency Keys With Payload Digests

Storing payload_sha256 alongside idempotency_key turns accidental key reuse with a modified quantity into an immediate, auditable transaction rollback.

Run Structured Fault Checks Before Calling the LLM
